## 3. 用户故事

### US-01: 历史案件快速入库

```
作为 法务经理
我想要 批量导入历史案件材料
以便于 建立案例知识库
```

**验收标准**：
- [x] 提供目录路径，CLI 自动扫描发现所有案件材料
- [x] 支持 docx/pdf/txt/md 四种格式
- [x] 自动识别案件基本信息（案号/原告/被告/案由/法院）
- [x] 扫描结果可预览，确认后入库

### US-02: 新案材料结构化提取

```
作为 律师
我想要 从案件材料中提取结构化信息
以便生成规范的法律文书
```

**验收标准**：
- [x] 支持 D1-D5 五维度提取（事实认定/法律依据/攻防策略/证据体系/赔偿裁量）
- [x] 提取结果格式规范（Markdown + JSON）
- [x] 可选择 AI 引擎（Ollama/OpenAI/Claude）
- [x] 提取结果可审核后入库

### US-03: 相似案件匹配

```
作为 律师
我想要 检索相似历史案件
以便 参考成功策略
```

**验收标准**：
- [x] 支持案号/原告/被告/案由关键词检索
- [x] 返回匹配案件的完整信息
- [x] 可查看案件关联的 artifacts

### US-04: 文书模板管理

```
作为 法务经理
我想要 管理文书生成模板
以便生成规范的法律文书
```

**验收标准**：
- [x] 支持 4 类文书模板（答辩状/质证意见/当庭陈述/证据目录）
- [x] 模板可新增/编辑/删除
- [x] 模板含元数据（template_id/category/usage_count）

### US-05: 批量历史案例查询

```
作为 法务经理
我想要 查看所有历史案件
以便 进行统计分析
```

**验收标准**：
- [x] 支持按年度/质量/案由筛选
- [x] 支持案号/原告/被告关键词搜索
- [x] 返回案件列表和统计信息

### US-06: 飞书 Bot 查询

```
作为 法务经理
我想要 在飞书中查询案件
以便 随时随地获取案件信息
```

**验收标准**：
- [ ] /case list — 返回案件列表
- [ ] /case search <关键词> — 返回匹配案件
- [ ] /case detail <case_id> — 返回案件详情

## 4. 非功能需求（NFR）

| 类型 | 需求 |
|------|------|
| **可用性** | CLI 命令响应时间 < 3s |
| **可靠性** | 扫描过程有进度提示，失败可重试 |
| **可维护性** | 所有代码有单元测试覆盖 |
| **可扩展性** | 支持多 AI 引擎切换 |
| **安全性** | PII 数据不硬编码，不外泄 |
