## 2. 目录结构特征

### 2.1 案件命名格式

```
{日期}-{案号}-{原告简称}诉{被告简称}-{案由/场景}-{负责人缩写}
```

示例：
- `240116-(2023)京0491民初23751号和23752号-TME诉雷石、特斯拉诉讼材料-WJY`
- `250904-纽凯诉雷客，金麦客、杭州当贝著作权纠纷-13392号-四川自由贸易试验区人民法院-HS`

### 2.2 内部目录结构

部分案件含多层嵌套子目录：
```
案件目录/
├── 原告文件/
├── 被告文件/
├── 程序性事项/
│   ├── 起诉状.pdf
│   ├── 答辩状.pdf
│   └── 传票.pdf
└── 实体性事项/
    ├── 判决书.pdf
    ├── 证据清单.pdf
    └── 授权文件/
```

## 3. 提取流程

### 3.1 扫描阶段

```bash
# 对单个案件目录扫描（递归3层）
python3 bin/extract.py scan "/path/to/case" --dry-run --max-depth 3

# 批量扫描脚本
./scripts/batch_scan.sh /path/to/year_folder
```

### 3.2 解析阶段

```bash
# 解析文件内容
python3 bin/extract.py scan "/path/to/case" --max-depth 3
```

### 3.3 AI 提取阶段

```bash
# 使用 Mock 引擎快速预览（无需配置）
python3 bin/extract.py scan "/path/to/case" --ai --engine mock

# 使用 Ollama 引擎（需本地安装）
python3 bin/extract.py scan "/path/to/case" --ai --engine ollama
```

### 3.4 校验与入库阶段

**校验清单**：
- [ ] 案号格式正确
- [ ] 原告/被告名称完整
- [ ] 案由准确
- [ ] D1-D5 维度完整
- [ ] 内容无明显错误

**入库命令**：
```bash
# 确认入库（需人工确认）
python3 bin/extract.py scan "/path/to/case" --ai --import
```

## 4. 提取标准

### 4.1 案件基本信息

| 字段 | 来源 | 格式要求 |
|------|------|---------|
| case_name | 目录名 | 完整案件名称 |
| case_number | 目录名/判决书 | 标准法院案号格式 |
| plaintiff | 目录名/起诉状 | 公司全称 |
| defendant | 目录名/起诉状 | 公司全称 |
| cause | 目录名/判决书 | 案由标准表述 |
| result | 判决书 | 结案/撤诉/调解等 |
| year | 目录名 | 2024/2025/2026 |

### 4.2 D1-D5 提取要求

| 维度 | 必须提取 | 最小内容 |
|------|---------|---------|
| D1 事实认定 | ✅ | 当事人信息、案件背景、争议焦点 |
| D2 法律依据 | ✅ | 适用法条、法律关系 |
| D3 攻防策略 | ✅ | 原告诉请、被告抗辩（按优先级） |
| D4 证据体系 | ✅ | 证据清单、质证要点 |
| D5 赔偿裁量 | ✅ | 赔偿请求、裁量因素、预估区间 |

### 4.3 提取物分类

| 类型 | artifact_type | 来源材料 |
|------|--------------|---------|
| 抗辩论证链 | defense_argument_chain | 答辩状、代理词 |
| 质证策略 | cross_exam_strategy | 质证意见 |
| 证据结构 | evidence_structure | 证据清单、证据目录 |
| 法律推理链 | legal_reasoning_chain | 法律分析意见 |
| 量化分析 | quantitative_analysis | 赔偿计算、传播统计 |
| 应变话术 | contingency_response | 应变准备 |
| 当庭陈述 | court_statement | 当庭陈述稿 |
| 关键事实 | case_key_facts | 判决书、案件摘要 |

### 8.5 改进建议

1. **优化正则表达式**：
   - 支持更长的案号匹配（当前截断问题）
   - 处理"东省""川省"等OCR截断情况
   - 排除公证书编号、检测报告编号等非案号内容

2. **增强文件名推断**：
   - 从目录名直接推断案号/案由
   - 目录名格式：`{日期}-{案号}-{原告}诉{被告}-{案由}`
   - 可直接解析提取案号和案由

3. **文件完整性检测**：
   - 在扫描阶段检测关键文件缺失
   - 标记缺少起诉状/判决书的案件

4. **OCR后处理**：
   - 过滤"东省""川省""故请法院"等明显截断
   - 还原为"广东省""四川省""管辖法院"等完整名称
