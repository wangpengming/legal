# case-intelligence 模块规格

> 模块：同质化案件文档检索与规则系统 · 集成日期：2026-08-17（并入 legal/modules/）
> 版本：v3.0 · 状态：planning（方案设计阶段）
> 作者：张洋 - 法务部

## 1. 一句话定义

把法务部门的历史案件卷宗、审核经验、检查清单全部结构化存储，让文员在新案件到来时能快速检索历史参考、按清单逐项审核、持续积累经验。**搜得到、看得懂、用得上，不做 AI，只做检索。**

## 2. 核心对象（三对象模型）

| 对象 | 载体 | 说明 |
|------|------|------|
| 案件 | NocoDB `cases` 表（31 字段） | 案号/案由/当事人/金额/审核结论等结构化数据 |
| 文档 | Paperless-ngx | 判决书/起诉状/证据 PDF，OCR 后全文可检索 |
| 规则/清单 | NocoDB `checklists + rules` 等 | 经验积累，按案由自动匹配（数据库筛选，非 AI） |

## 3. 技术架构

- **NocoDB**（:8090）：案件录入、检查清单、审核记录、经验规则、批注记录（6 张表）
- **Paperless-ngx**（:8091）：文档上传、OCR、全文检索、标签分类
- 两系统通过案件表「关联文档」字段做**弱关联**（手工粘贴链接），不做数据库外键
- 唯一自研代码：Word 批注/修订提取脚本（python-docx + docx-revisions，约 200 行）
- 部署：单机 10.10.11.37，Docker Compose 7 容器，~2GB RAM / ~10GB 磁盘

## 5. 演化路线

1. **Phase A 部署**：安装 7 容器 + 建 6 张表 + 预设初始检查清单（约 1.5 小时）
2. **Phase B 试点录入**：历史案件结构化录入 + 卷宗批量入库（consume 目录）
3. **Phase C 规则积累**：审核记录回流 → 规则表沉淀 → 清单版本化
4. **远期**：统一入口（Nginx 导航页）· 文档↔案件强关联（Paperless REST API 按案号回填）

## 6. 与 legal 其他模块的关系

| 模块 | 关系 |
|------|------|
| litigation-system | 互补：litigation 管**飞书结构化案件数据**的分析统计；case-intelligence 管**卷宗文档**的检索与审核规则；未来可由 litigation 详情页链接跳转本模块文档 |
| court-doc-generator | 无直接依赖（出庭手续生成，面向新案件准备材料） |

## 7. 待确认事项（引自方案设计 v3 第 10 节）

1. 表结构合理性（6 张表字段增减）
2. Word 批注提取方案是否接受
3. 检查清单由谁维护（管理员预设 vs 文员补充）
4. 是否需要权限控制 / 统计报表 / 统一入口
5. 中文 OCR 社区镜像 vs 官方镜像自建
6. 「文档↔案件」弱关联是否接受
