# SPEC-enhancements-v2.2.5 — 扫描多图合并 + OCR 识别鲁棒化

> 对应 backlog：2026-08-22「拍照扫描多图合并 + OCR 识别鲁棒化（增强）」
> 前置：v2.2/v2.2.1 已归档，本规格在 dev 分支增量演进。

## 1. 背景与动机

用户实测反馈（补充需求原话）：

> 起诉状往往不是一个图片和文档，有可能有多个图片或文档才能识别所有的信息。
> 所以扫描功能要支持上传多个图片，然后识别并整合信息。
> 另外……识别的信息不够准确。

两个问题点：

1. **单文件限制**：v2.2 扫描仅支持单文件上传；真实起诉状常为多页/多图（如「此致 XX人民法院」在末页），信息分散在不同图片。
2. **识别准确率不足**：真实拍摄照片（形近字误读、正文噪声混入当事人、案由不在标签行）导致字段错漏。

## 2. 方案

### 2.1 OCR 识别鲁棒化（scan_service.py）

- **双 PSM 交叉 OCR**：`_PSM_MODES = (3, 6)` — psm3（自动分页，正文当事人全名准）+ psm6（统一文本块，印刷标签行准）；逐图双通道各跑一次，结果拼接互补（`=== 图片 N ===` 分段）。
- **法院形近字还原**：`_FUZZY_COURT_CHAR` 映射（法→活/洁/合/泊/泫/沽，院→区/完/皖/立/阮）；正则 `([\u4e00-\u9fa5]{2,10}人民)([\u4e00-\u9fa5]{1,2})` 抽取，「人民人民法院」防重复拼接；多候选取最长。
- **当事人全候选评分截断**：`_extract_party(text, role)` — 身份词/分隔符清洗 → 分句 → `_PARTY_STOP_WORDS`（住所地/地址/统一社会信用代码/法定代表人等）截断 → **公司尾词截断**（有限责任公司/股份有限公司/有限公司/公司，解决「…有限公司经合法转授权获得了…」正文噪声）→ 机构词评分选优（`score = 10×机构词 + min(len,20) + 长度分段分 − len/100`）。
- **案由四级抽取**：①案由标签行正则 → ②`_CAUSE_KEYWORDS` 复合词表（信息网络传播权→侵害作品信息网络传播权纠纷等 9 条）→ ③`{2,8}纠纷` 正则 + 前缀清洗（本案系/系/属/因/为）→ ④侵权/纠纷关键词兜底。

### 2.2 多文件 API（backend/app/api/scan.py）

- `POST /api/v1/scan/scan` 签名扩展：`files: Annotated[list[UploadFile] | None, File(...)]`（FormData 同名多次 append）+ 保留 `file` 单文件参数向后兼容。
- 处理链：逐文件类型/大小校验 → 存 `.run/` 临时文件 → PDF 用 pdftoppm(r=200) 转图 → `img_paths` 合并 → `extract_text(img_paths)` 统一识别 → `extract_fields` → `finally` 统一清理临时文件。

### 2.3 前端多选（ScanModal.tsx + lib/scan.ts）

- `input multiple`：一次选择多张图片/PDF，列表展示（名称 + KB + 移除按钮），collect 后点「开始识别（N 个文件）」批量上传。
- `scan.ts` 新增 `scanUploadFiles(files: File[])`：FormData 逐个 `form.append("files", f)`；`mapFieldsToCaseForm` 沿用空格噪音清洗。

### 2.4 整合语义

多图文本按页拼接后统一字段抽取 → 字段分散在不同页时自动合并（如法院在末页「此致」段、当事人与诉讼请求在前页）。

## 5. 备注

- 起诉状通常无案号/开庭时间/立案日期，识别为 None 属合理预期，前端仅展示非空字段。
- 形近字映射表与案由复合词表为启发式集合，随真实样本逐步扩充。
- 手写体/低清照片仍可能有个别字段漏识别，Modal 内保留二次手工修改后保存。
