## 输入
- 一个明确业务目标但尚未启动的项目
- 希望利用 AI 逐步完成开发的小白或非专业开发者
- 典型案例：公司内部法务工具（如出庭手续生成器，参见 /Users/zhangyang/Desktop/Ai工作/9.琐事/AI应用/出庭手续生成器/）

## 步骤
1. **阶段 0：业务理解与立项**
   - 让 AI 扮演角色，明确背景、目标、约束（如本地部署、数据安全）。
   - 输出：功能列表、技术选型建议、目录结构初稿、MVP 范围。
2. **阶段 1：MVP 启动**
   - 确定技术栈（如 Streamlit + SQLite + python-docx + PyMuPDF），初始化项目结构，实现最简可用版本（Hello World + 基础数据模型）。
   - 定义模板占位符规范（如使用中文全角【】）。
3. **阶段 2：核心功能实现**
   - 逐个攻克核心逻辑（Word 转 PDF、PDF 合并、缩略图、ZIP 打包），注意处理异常和边界情况。
4. **阶段 3：服务化与部署**
   - 编写管理脚本（start/stop/restart/status），处理端口冲突、进程守护、健康检查。
   - 端口固定非通用端口（如 18501 避开 8501）。
   - 兼容 macOS bash 3.2（不用数组 += 语法）。
   - 创建双击启动入口（如 `.command`）。
5. **阶段 4：UI 与体验优化**
   - 定义视觉风格（Vercel/Linear 风格，配色、字体、圆角、克制渐变）。
   - 实现高级交互（如浏览器内 PDF 预览，PDF.js 全内联 base64 data URI 方案）。
6. **阶段 5：故障排查与稳定性**
   - 建立常见错误清单和排错模板（日志查看、端口占用检查、PID 文件验证）。

## 输出
一份完整的、分阶段的开发指导文档及对应的提示词模板。
完整示例已保存到项目 docs/PROMPTS.md，包含 13 个独立可执行的提示词（阶段 0-5）。

## 注意事项
- 不要一次性做完所有功能，先跑通 MVP。
- 服务管理脚本是基础设施，务必提前写好。
- 保留降级方案（如 macOS 系统 Preview）作为兜底。
- PDF.js 浏览器内预览是最大坑：必须用 `eval(atob(mainB64))` 而非 `new Function()`，因为 var pdfjsLib 不会从 Function 作用域泄漏。
- 适合小白：从阶段 0 业务理解起步，逐步推进，每阶段都有明确验收标准。
