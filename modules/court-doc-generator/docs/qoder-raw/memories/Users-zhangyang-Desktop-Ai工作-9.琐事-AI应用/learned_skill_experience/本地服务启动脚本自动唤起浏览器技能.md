## Input
- 本地服务启动脚本（如 .command, .sh）
- 服务端口号或健康检查 URL

## Steps
1. **分析现有逻辑**：检查启动脚本中是否存在“服务已在运行”时直接 `exit` 的逻辑，这会导致后续的浏览器打开命令被跳过。
2. **统一入口处理**：在顶层启动脚本（而非子脚本）中执行服务启动命令，并捕获退出码。
3. **健康检查确认**：使用 `curl -sf <health_url>` 验证服务是否真正在线，避免假阳性。
4. **条件触发浏览器**：若健康检查通过，根据操作系统（如 macOS 用 `open`）自动打开浏览器；若失败则保留终端窗口显示错误信息。
5. **延迟退出**：在成功打开浏览器后添加短暂 `sleep`，确保浏览器进程有时间响应后再关闭终端窗口。

## Output
双击启动脚本后，无论服务是新启动还是已存在，均能自动弹出浏览器访问应用，且启动失败时能保留错误日志。

## Notes
- 避免在子脚本中处理 UI 交互（如 open），应集中在入口脚本处理。
- 必须包含健康检查，防止服务进程存活但未就绪时误开浏览器。
