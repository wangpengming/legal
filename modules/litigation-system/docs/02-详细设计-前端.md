## 1. 设计总则

### 1.1 设计目标

1. **数据密度优先**：638 条实测数据在 1440×900 下一屏展示最大信息量，对标 Metabase/BI 工具而非营销页；
2. **业务主轴的表达**：一切页面围绕「被告视角·音乐版权批量诉讼」——重点呈现同质案件聚合（同一版权方 N 案、单曲多案、系列案树），而非通用 CRM；
3. **可解释性**：任何数字可下钻、任何结论带来源、任何口径带定义（SPEC 5 的四、五两条落地）；
4. **原始/清洗并存**：脏数据不藏不删，角标+对照可见（清洗是 P0 卖点而非黑箱）；
5. **双模式 AI 同源**：Mode A 对话面板与 Mode B 报告共享同一套检索语料与口径，UI 上来源脚注组件统一。

## 2. 设计系统（Design Tokens）

> 全部 token 用 CSS 变量承载（shadcn theme 结构），亮/暗双主题共一套语义变量，见 research/04 §2。以下为定稿值。

### 2.1 语义色板（定稿）

| Token | 亮色 | 暗色 | 使用 |
|-------|------|------|------|
| `--primary` | `#2563EB` | `#3B82F6` | 主操作按钮、选中、链接、焦点环 |
| `--primary-fg` | `#FFFFFF` | `#0F172A` | 主按钮文字 |
| `--success` | `#16A34A` | `#22C55E` | 我方占优（胜诉/驳回对方/撤诉占比高） |
| `--danger` | `#DC2626` | `#EF4444` | 判赔、超期未结、同步失败、终本新警 |
| `--warning` | `#D97706` | `#F59E0B` | 和解待定、执行中、终本、洗标待确认 |
| `--info` | `#64748B` | `#94A3B8` | 中性提示、无依据标记、「标的缺失」 |
| `--muted` | `#64748B` | `#94A3B8` | 次要文字、口径脚注 |
| 灰阶 | slate 系（bg `#F8FAFC` / surface `#FFFFFF` / border `#E2E8F0`） | 反转（bg `#0F172A` / surface `#1E293B` / border `#334155`） | 层级 |

**约束**：业务状态色**全站唯一绑定**（§2.2 映射表），代码中禁止散落 hex；语义色只表达业务状态或系统状态，不表达导航空状态。

### 2.2 状态 → 颜色映射表（全站唯一来源，组件与图表共用）

**案件状态（21 项枚举，按生命周期分组）**：

| 分组 | 状态 | 色 | 图标 |
|------|------|-----|------|
| 已了结（终态·我方占优） | 已结案(胜诉类)、已撤诉、已和解 | `success` | ✓ |
| 已了结（终态·判赔） | 已结案(判赔类) | `danger` | ✕ |
| 审理中 | 一审待判决、二审待判决、等待开庭、排期中（实测枚举内同类） | `primary` | ● |
| 执行/终本 | 强制执行中、执行终本、协助执行 | `warning` | ⚠ |
| 异常/特殊 | 破产重整中、破产清算中、撤诉待办、其他 | `info` | ⧗ |

（注：状态与结案原因概念重叠，UI 原则 = **状态=当前生命周期位置，结案原因=终局定性**；两字段并列展示时用分区标题区分，不强行合并。）

**结案原因（15 项，需求文档 4.1 #19）→ 胜负三色**：

| 判定 | 结案原因枚举 | 色 |
|------|--------------|-----|
| 胜（口径A 胜集） | 胜诉 / 驳回上诉维持原判 / 判决驳回对雷石的诉求 / 裁定驳回雷石的诉讼请求 / 裁定驳回对雷石的诉讼请求 | `success` |
| 败 | 判赔 | `danger` |
| 中性 | 双方和解 / 原告撤诉(归并后) / 裁定驳回追加请求 / 按撤回起诉处理 / 撤回上诉 / 终本 / 一审驳回对雷石的起诉（程序性，无胜负） | `info`/`warning`（终本=`warning`） |

**其他映射**：支付主体（雷石=`primary`、雷客=`info`、诉讼相对方=`warning`）；业务线 8 项用固定色序循环（调色板：9 色区分，ECharts 统一 palette）。

### 2.3 字体、排版与数字

| 项 | 定稿 |
|----|------|
| 西文/数字 | Inter（v4+ 自带 tabular 特征）；无则系统栈 `-apple-system, "Inter", "PingFang SC", "Microsoft YaHei"` |
| 中文 | PingFang SC / Microsoft YaHei fallback |
| 数字专用 | 金额、统计数字、案件数一律 `font-variant-numeric: tabular-nums; letter-spacing: -0.01em`（对齐全靠它） |
| 字号 | `13` 表格/正文 / `12` 次要/脚注 / `14` 控件/卡片标题 / `16` 区段标题 / `20` 页面标题 / `24~32` 大数字（StatCard 数值 24px，总览 hero 值 32px） |
| 行高 | 表格 28px 紧凑（默认）/ 32px 舒适（表格右上密度切换）；正文 1.6 |
| 权重 | 大数字 SemiBold 600；标题 Medium 500；正文 Regular 400 |

### 2.4 布局、圆角、阴影、间距

- 基准栅格 4px；内容区左右内边距 20px；相邻卡片 gap 12~16px；
- 圆角：大卡 12px / 控件与按钮 8px / 徽标与 tag pill 999px；
- 阴影两层：卡片 `0 1px 2px rgba(15,23,42,.04), 0 1px 1px rgba(15,23,42,.03)`；浮层（弹层/抽屉/下拉）`0 4px 6px -2px rgba(15,23,42,.06), 0 12px 32px -8px rgba(15,23,42,.18), 0 0 0 1px rgba(15,23,42,.05)`；
- 表格内分隔用 1px `--border`；卡片之间不叠加边框外阴影层级，靠背景色区分。

### 2.5 动效规范（禁止装饰性动效）

| 场景 | 规格 |
|------|------|
| 数字滚数 | 变化时 400ms ease-out 滚数（仅 StatCard/hero 大数字；表格单元格不滚） |
| 图表过渡 | ECharts `animationDuration: 400, animationEasing: 'cubicOut'` |
| 抽屉/弹层 | 200ms ease-out 进出；遮罩同时淡入 |
| 骨架屏 | 灰阶渐变 shimmer 1800ms 循环；**禁止旋转圈/菊花** |
| 页面切换 | 无整体转场（避免干扰读数）；仅路由后数据骨架屏 |
| hover | 表格行 `bg-muted/40` 过渡 120ms；按钮按下缩放 0.98 |
| 同步状态条 | 进度条推进 300ms ease；成功变绿后 1.5s 自动折叠 |

### 2.6 图标与徽标

- 图标库：lucide-react（shadcn 生态默认），业务语义图标固定映射（案件=Scale、歌曲=Music2、对手方=Building2、费用=Wallet、同步=RefreshCw、导出=Download）；
- 徽标（Badge）四种：`status`（状态色点+文字）、`dirty`（脏数据黄色角标 "+N"）、`source`（来源标：📂本地 / ⚖️案例 / 📜法规）、`fresh`（"今天"。用于开庭日程）；
- 脏数据角标规则：字段清洗级别=2 且原值≠清洗值 → 字段右上 `dirty` 徽标；列表行汇总显示 `清洗 1 项` 下拉。

### 2.7 空/错/脏三件套（统一组件，全局复用）

| 状态 | 视觉 | 文案模式 | 动作 |
|------|------|----------|------|
| 空态（无数据） | 居中插画位（简单几何）+ 主文案 + 说明 | "没有匹配的案件" + "试试放宽筛选条件，或检查同步是否完成" | 「查看同步状态」「清除筛选」主/次按钮 |
| 错误态 | 红色警示条/卡片 | "加载失败：网络错误 (502)" + 简明原因 | 「重试」「查看详情(堆栈)」 |
| 脏数据态 | 黄琥珀提示条（列表页顶部）+ 字段级角标 | "检出 6 个字段存在疑似脏数据，已标记待确认" | 「查看清洗明细(跳词典页)」「忽略」 |

## 3. 全局组件规格

### 3.1 侧栏 Sidebar

- 宽 240px / 折叠 64px；折叠按钮在侧栏底部；
- 分组标题 11px 大写灰字；当前项高亮 `--primary` 左边条 2px + 浅蓝底；
- 计数徽标：总览页显示「在办 47」「下周开庭 5」实时数字（可不做实时，至少导航徽标随数据刷新）；
- P1/P2 未实现项：名称置灰 + 「Ph2/Ph3」小标签，点击弹提示；
- 底部：版本号 + 「反馈问题」mailto 链接。

### 3.2 顶栏 Topbar（48px，全站常驻）

| 元素 | 规格 |
|------|------|
| 全局检索框 | 占位「检索案号 / 当事人 / 歌曲 / 笔记… (/)」，宽度 300~460px 自适应；聚焦显示弹出联想（热门案由、最近当事人）|
| `/` 快捷键 | 任意页面按 `/` 聚焦输入框；按 `Esc` 失焦；Enter 跳 `/search?q=…` |
| 同步状态徽标 | 三态：绿点「已同步 08-13 03:00」/ 黄点「同步中 63%」/ 红点「同步失败」→ 点击展开同步抽屉（进度、日志入口）|
| 主题切换 | ☀/🌙 图标切换，localStorage 持久化，默认跟随系统（`prefers-color-scheme`）|
| 业务线快捷筛选 | 下拉（全部/VOD/IPTV·OTT/车载/雷客/人力/哇屋/研发/默霆），选择后全站列表页追加 `biz=` 条件（浅提示条可撤销）|

### 3.3 同步状态条（全局告警，页面顶部）

- 正常：不显示（仅 Topbar 徽标）；
- 进行中：细进度条（0~100%，**无旋转圈**）+ 「正在同步案件表 35 字段 · 第 3/7 批」；
- 失败：红色条「同步失败：飞书 API 超时 (20s) · 已自动重试 2/3」+ 「立即重试」「查看日志」；
- 陈旧：距上次成功 >48h 显示琥珀条「数据可能滞后：距上次同步 3 天 6 小时」+ 「立即同步」。

### 3.4 数字卡片 StatCard（总览/分析重用）

```
┌─────────────────────────────┐
│ 在办案件数        [口径?]    │  ← 右上口径 icon，hover 出 tooltip 定义
│     47                      │  ← hero 数字 32px tabular-nums，点击下钻
│  ▲ 12 本月新增 · 环比 +8%   │  ← 增量行（同比/环比，无数据显「—」）
└─────────────────────────────┘
```

- 4 列布局（<1440 时 2 列）；数值区为 <button> 可点击 → 弹「明细抽屉」（§3.8）；
- 口径 tooltip 内容来自 `/metrics` 定义（如胜诉率口径 A/B 的完整集定义）；
- 空值显示 `—`，禁止显示 0 冒充无数据；环比无基期显示「—」。

### 3.5 筛选面板（组合检索/多维分析共用）

- **字段驱动生成**：前端拉 `/api/v1/metadata`（35 字段字典+枚举+口径）动态渲染筛选器，后端加字段无需改前端；
- 筛选器类型映射：枚举字段（案由/业务线/状态/结案原因/支付主体）→ 多选 chip 下拉；年份 → 单选+「全部」；金额 → min/max 双输入 + 单位标注「元」；日期 → 区间日历；文本 → 关键词（FTS）；「是否涉歌曲」→ 开关；
- 交互：选中条件实时拼成条件串显示（如 `年份=2023 · 业务线=车载 · 结案原因=双方和解`）；每条件可独立移除；「保存筛选集」命名入库（进 /tags 或独立 saved_filters 表）；
- URL 同步：条件变化即写入 query string（防抖 400ms，浏览器后退可回退）；
- 底部操作行：`重置` / `保存为视图` / `导出当前结果（口径附注）`；
- 列表中选中 N 行 + 筛选并存时，横幅「已选 23 件 · 满足当前筛选」避免误导。

### 3.6 数据表格基座（全站列表统一）

| 规格项 | 值 |
|--------|-----|

| 固定列 | 首列「案号」固定（选中态可见，横向滚动不丢上下文） |

### 3.7 图表封装（ECharts 统一规范）

- 主题：亮/暗两套注册，令牌与 §2.1 语义色绑定；`grid: {top: 40, right: 16, bottom: 28, left: 56}`；
- 数字格式：数值轴 `tabulate+narrowNoBreakSpace` 千分位；金额轴加 ¥；tooltip 一律含「口径说明」第二行（灰色小字，如"对方诉求支持率=支付总金额/标的，样本 n=312"）；
- 交互联动：折线/柱图 `bindType: 'click'` → 触发回调把条件回填筛选面板/表格（§8.1 协议）；
- 图形可导出（toolbar 缩放/保存图片/数据视图 三件必备）；
- 无数据图形显示空态插画位而非空坐标系。

### 3.8 明细抽屉（数字下钻通用件）

- 从任意 StatCard/图表 tooltip「查看明细」触发，右滑抽屉 480px（<1280 全宽）；
- 头部：标题「在办案件数 · 47 件」+ 口径定义 icon + 「导出」；
- 主体：紧凑表格（同表格基座，列自动缩为 id/案号/对手方/标的/状态/收案日期）；
- 底部：分页 20/页 + 「数据截至 xx 同步」脚注；
- **规则：所有结论性数字必须可达此抽屉，禁止只给数字不给依据**（SPEC 5.4）。

### 3.9 原始/清洗对照

- 字段级：清洗级别≥1 的字段，详情页字段行内右侧 `raw` 图标 → hover tooltip 显示原始值（截断 120 字符，全文可展开）；或点击切换「清洗值 ↔ 原始值」；
- 页面级：详情页工具条「显示原始视图」开关——整页字段渲染为原始值，清洗徽标全部点亮，「清洗前/后」diff 高亮（word-diff 风格）；
- 列表级：脏数据行左侧竖色条 `warning`，行尾「脏 1」徽标，hover 列出涉及字段。

## 8. 跨页面交互契约

### 8.1 表图联动协议（全局约定）

统一事件总线（Zustand `useFilterStore`）：

```text
任意页面 filter store 变更
  → ① 当前页表格/图表订阅刷新
  → ② query string 同步（防抖 400ms）
  → ③ 图表 click（维度值）→ 合并入 store → 触发 ① ②
```

约束：无单向锁死——表格筛选可驱动图表，图表点击可回填表格，循环由「同一 store 单写源」规避；跨页跳转（如总览→检索）携带 store 当前条件。

### 8.2 URL 状态与深链

- 列表类页面全部条件可序列化（§4.2）；详情/画像/单曲支持深链；
- 返回链：详情页面包屑记忆来源（检索条件）；跨页跳转换页保持滚动位置（列表页滚动记忆 sessionStorage）。

### 8.3 打印与导出（报告友好）

- `@media print`：隐藏 Sidebar/Topbar/交互控件；详情页打印仅头部+五区+时间轴（A4 一页优先）；统计页打印当前图表（矢量）；

## 9. 性能与可访问性

### 9.1 性能预算（对照需求 5 非功能）

| 项 | 预算 | 手段 |
|----|------|------|
| 首屏 LCP | <1.5s（P0 页） | 路由级 code-split；列表虚拟滚动；Charts 按需加载 |
| 检索返回 | <300ms（638~2 万行） | 本地 SQLite FTS 后端 + 前端防抖 |
| 表格滚动 | 60fps（10 万行） | TanStack 虚拟滚动 + 行 memo 化 |
| 图表渲染 | <500ms | ECharts 按需引入 + 单例实例池（页面切换 keep-alive） |
| 同步中查询 | 不受阻 | 写读分离（后端保证），前端仅展示状态条 |

### 9.2 可访问性（WCAG AA 尽力）

- 焦点泄露管理（抽屉/弹层 focus trap + Esc）；focus-visible 环 = `--primary` 2px offset；
- 颜色不作为唯一信息通道（状态=色+图标+文字三保险）；对比度亮/暗主题均 ≥4.5:1（text 13px 起）；
- 表格提供 `<caption>`（屏读标题）；图表带 aria-label 数据摘要文本；
- 动效 `prefers-reduced-motion` 关闭滚数/过渡。

### 9.3 浏览器

Chrome/Edge 最新 2 版本（无 IE）；`layer` 与 `color-mix()` 可用性确认（Tailwind v4 默认）；离线能力：除 AI/案例库外全部页面本地缓存可读（PWA 壳可选，非本期）。
