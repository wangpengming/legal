# 调研 01 · 网络判决数据源（"网上判决"支柱替换选型）

> 调研日期: 2026-08-13
> 调研方法: WebSearch + 官网实测（人民法院案例库 rmcourt）
> 目的: 验证 SPEC v0.1「三源交叉验证」中 ⚖️网上判决 支柱的可得性，输出替代数据源选型结论
> 结论摘要: **裁判文书网不可作为唯一支柱 → 三梯队方案：人民法院案例库（官方免费，要旨权威）＋商业法律库（全量覆盖）＋裁判文书网（兜底）**

---

## 1. 裁判文书网现状（为什么不能继续依赖）

### 1.1 上网量断崖式下降（数据出处：《中国经济周刊》2024-01 统计）

| 年份 | 上网量变化 | 来源 |
|------|-----------|------|
| 2021 | -29%（较上年） | 人民日报《中国裁判文书网十年不易》 |
| 2022 | -46%（较 2021） | 同上 |
| 2023 | -64%（较 2022） | 同上 |

> 累计 2020→2023 三年降幅约 73%（1920 万件→约 511 万件）。2024 年至今未回升迹象。

### 1.2 检索能力官方承认弱化

- 最高法（2024-02 新闻发布会回应）："上网文书数量虽已过亿，但只是简单累加，缺乏关键词和裁判要旨，很难做到精准检索"——**官方承认检索不便利**；
- 2023-12 流传最高法拟建「全国法院裁判文书库」：**仅限法院干警内网使用，不向社会开放**（《财经》报道）——公众可得的官方文书路径进一步收窄；
- 2021-07 起裁判文书网经历"针对性整改"，定向浏览/批量下载等能力持续收紧。

### 1.3 结论

对「历史案件分析」而言，裁判文书网的可作为：
- ❌ 不能作为「批量、结构化、带要旨」的检索支柱；
- ⚠️ 仅可作**定向案号核验/兜底**（特定案件的文书原文确认）；
- ⚠️ **API/批量抓取合规风险高**（robots 限制 + 整改期政策不稳），禁止研发期依赖爬虫。

## 2. 替代数据源矩阵

### 2.1 人民法院案例库（rmfyalk.court.gov.cn）—— 官网实测 2026-08-13 ✅

| 维度 | 实测结果 |
|------|----------|
| 公开性 | 免费公开访问，**无需登录即可检索**（登录用于收藏/笔记/反馈） |
| 收录量 | 官网首页显示 **3,927 篇**（含刑事/民事/行政/国家赔偿/执行五类；2024-02 上线，首批 3,711 件） |
| 分类 | 指导性案例（最高法发布）/ 参考案例（最高法审核入库）两类 |
| 检索维度 | 全文/标题/编号/案号/案由/案件类型/审理程序/审理法院/法院级别/文书类型/关键词/裁判日期 + **高级检索（精确/模糊）** |
| 内容结构 | 基本案情 / 裁判理由 / **裁判要旨**（官方审核，结构化）——正好补裁判文书网"缺关键词和裁判要旨"的短板 |
| 权威性 | 最高法统一建设；**最高法明确要求各级法院审理案件应当检索参考**（新华社 2024-05-07） |
| 个人能力 | 我的收藏/我的笔记 → 可作「同质化案例库」人工沉淀池 |

**价值判断**：
- ✅ 免费、权威、带要旨、结构化字段完善，是「网上判决」支柱的**官方替代首选**；
- ⚠️ 覆盖量有限（数千篇），**不能取代商业库做全量覆盖**；案由优先级中「侵害作品信息网络传播权纠纷」等版权案已有多篇入库（最高法首批已覆盖多发案由）；
- ⚠️ 无公开 API（官方未开放批量接口），接入方式为：**人工/Agent 在页面检索 + 结果人工确认后入本地"外部案例表"**，自动化程度受限于反爬与 ToS。

### 2.2 商业法律库（备选与覆盖补充）

| 库 | 性质 | 覆盖 | API/接入 | 适用评级 |
|----|------|------|----------|----------|
| 北大法宝「类案检索平台」（cases.pkulaw.com） | 国内头部综合库 | 民事/刑事/行政/执行案例全量 + 法规 + 类案报告生成 | 有对外 API（企业版，付费） | ⭐⭐⭐ 覆盖全、有类案报告能力；成本中高 |
| 威科先行 | 国际背景综合库 | 法规/案例/实务指南/专家解读 | 机构订阅制（API 需商务） | ⭐⭐ 权威但偏涉外/合规场景，版权批量案覆盖一般 |
| Alpha（promote.alphalawyer.cn） | 律所作业系统 | 案例/裁判文书检索 + 案件管理一体化 | 会员制为主，API 待商务 | ⭐⭐ 功能全但绑定其作业系统，轻量接入重 |
| 无讼/聚法案例 | 互联网法律社区 | 案例检索 + 报告 | 网页检索为主，API 弱 | ⭐⭐ 检索体验好，数据量中等 |
| 得理法搜 | AI 加持检索 | 案例/法条语义检索 | AI 对话式，API 弱 | ⭐⭐ 适合交互式调研，不适合系统化接入 |

### 2.3 其他官方源

| 源 | 定位 |
|----|------|
| 国家法律法规数据库（flk.npc.gov.cn） | 📜法律法规支柱：权威免费、结构化条码，作为「法律条文」锚定源 |
| 最高人民法院公报（gongbao.court.gov.cn） | 权威案例补充（公报案例），量少但覆盖新型问题 |

## 3. 选型建议（供 Phase 2 落地）

### 3.1 三梯队架构

```
⚖️ 网上判决支柱（渲染进报告/画像）
├── T1 人民法院案例库（免费·官方·要旨）      ← 答案 × 3 优先命中（权威性把关）
├── T2 商业库存量覆盖（北大法宝 API，首选）  ← 全量案由/年份检索（覆盖度把关）
│     备选：无讼（成本优先）/ Alpha（一体化优先）
└── T3 裁判文书网（兜底核对 + 文书原文）     ← 仅定向案号核验，禁批量
```

### 3.2 接入模式（推荐：半自动 + 人工复核）

1. Agent / 用户在 T1 检索「案由+关键词（被告/歌曲/侵权主体）」，命中后人工确认入本地 `external_cases` 表（案号、要旨、裁判日期、来源库、链接、确认人、确认时间）；
2. 同类案报告中，外部案例与本地历史分块展示，标注来源与"人工复核"徽标；
3. T2 API 接入（如预算批准北大法宝）后，检索可自动填充候选，仍需「确认入库」动作——**避免未审核外部数据污染本地统计**；
4. 每条外部案例带链接，报告可回链原文。

### 3.3 针对版权批量诉的先例预期

- 案例库已覆盖多发案由（首批含著作权类），涉「侵害作品信息网络传播权纠纷」的入库案例可在 Phase 2 预检时核实数量；
- 若案例库全量仍偏少（数千篇规模），T2（北大法宝类案）承担主要覆盖，T1 承担"要旨级权威参考"。

### 3.4 预算与合规提示

- 预算参考：北大法宝企业 API、威科先行机构订阅为万元级/年档；无讼、Alpha 会员为千元级/年档（以 2026 签约价格为准，需询价）；
- 合规：任何库均**只读 + 不转发 + 内部使用**；禁止从裁判文书网批量爬取；
- 决策点（Phase 1 结束前必须拍板）：是否采购商业库 → 影响 Phase 2 外部案例接入深度。

## 4. 结论（写回 SPEC v0.2 / 需求 4.4）

| 项 | 结论 |
|----|------|
| 裁判文书网 | 降级为 T3 兜底源，禁止批量依赖 |
| 第一接手 | 人民法院案例库（免费落地，Phase 2 即可开工，无需预算） |
| 全量覆盖 | 北大法宝 API（推荐）或替代库，**Phase 1 末商务决策** |
| 法律法规 | 国家法律法规数据库（免费权威） |
| 落地动作 | 本地 `external_cases` 表 + 半自动确认入库 + 报告分块标注来源/复核徽标 |
