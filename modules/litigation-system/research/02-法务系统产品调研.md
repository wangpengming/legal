# 调研 02 · 法务系统产品形态（对标与借鉴）

> 调研日期: 2026-08-13
> 调研方法: WebSearch（法律行业数字化产品案例）
> 目的: 为功能设计提供市场对标；明确我司系统与市面产品的差异点，避免照搬
> 结论摘要: 市面产品以「律所/银行法务全流程管理」为主；本案差异化为「**被告视角·版权批量诉讼·历史数据挖掘+AI 双模式**」

---

## 1. 市场玩家速览

|-----------|------|------------------|--------|

| 元典 Yodex | 大模型智慧法务管理平台 | 20+ 诉讼程序模板、40+ 案件进展模块化配置、精细化数据统计 | 🟢 程序模板化；案件进展配置化 |

## 2. 共性能力提炼（市面共识 = 不必重新发明）

1. **案件全流程阶段管理**（收案→应诉→开庭→判决→执行→归档）——本案由「案件状态 21 项 + 结案原因 15 项」承担，需在 UI 上呈现为可读流程而非裸枚举；
2. **统计报表/看板**（件数、标的、胜诉、费用、期限）——本案 M1/M3 已覆盖，**增量：口径版本化与来源可下钻**；
3. **画像能力**（法官、对方、律师画像）——民生智库已实证「法官历史审理情况」可行性；本案从「承办法官及联系方式」字段与外部案例库结合起步；
4. **AI 赋能**（问答、文书生成、风险识别）——本案 Mode A/B 双模式；**差异点：三源交叉验证 + 来源强制标注**是本案比市面产品更强的可解释性设计；
5. **风险监控/时限提醒**——本案「最近开庭时间」「结案期限」→ 待办/日程卡（S1）；可再加「超 6 个月未结」红线提醒（P1 可选）。

## 3. 我司系统差异化定位（不照搬的理由）

| 维度 | 市面产品默认形态 | 我司系统 |
|------|------------------|----------|
| 用户视角 | 律所/银行法务 = 原告/中立代理居多 | **被告视角**（版权方诉我司终端），关注抗辩、和解、判赔折让 |
| 案件结构 | 单案管理为主 | **批量系列案**（合并案件数、父记录、同一版权方 N 案） |
| 核心资产 | 流程协同 | **10 年历史数据 638 条 → 统计/画像/单曲判赔/类推** |
| 数据模式 | 录入驱动 | **飞书只读同步驱动**（零录入） |
| AI | 文书生成为主 | **双模式：对话（A）+ 外部 Agent 报告（B），三源验证** |
| 垂直特色 | 通用 | **歌曲维度分析**（涉歌曲清单表，市面无此先例） |

## 4. 对我司功能设计的直接输入

1. **案件状态可视化**：21 项状态不应裸列表——设计「状态机泳道/阶段条」呈现（已结案/审理中/执行/终本等），详情页给出阶段推进视图；
2. **待办与时限**：S1 增加「开庭日历 + 超期未结预警」（借鉴 iCourt 时限管理）；
3. **画像卡片**：对手方画像卡（S4）参考民生智库口径：累计件数、在办、判赔、法官关联案、和解史；
4. **批量操作**：系列案支持批量选中→批量打标/批量导出/批量查看合并（借鉴伙伴云批量诉讼）；
5. **AI 差异化**：报告结论强制「本地库/外部案例/法条」三源分块 + 复核徽标（成为产品卖点，写入 docs/02 AI 面板规格）。

## 5. 结论（写回 SPEC/设计）

| 项 | 结论 |
|----|------|
| 不照搬 | 不做律所级全流程协同（无多角色）、不做文书生成引擎（非核心） |
| 必做 | 状态阶段可视化、待办/时限卡、对手方画像卡、批量操作、报告三源标注 |
| 差异化 | 被告视角版权批量分析 + 歌曲维度 + 双模式 AI（来源可解释） |
| 参考实现 | 民生智库画像口径 / 伙伴云批量交互 / 元典模板化 / iCourt 时限管理 |
