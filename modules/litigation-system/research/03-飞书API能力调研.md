# 调研 03 · 飞书多维表格 API 能力与限制

> 调研日期: 2026-08-13
> 调研方法: 官网文档检索 + lark-mcp 实测调用交叉核验
> 目的: 核验 SPEC v0.2 同步引擎设计的关键约束（QPS、行数、公式字段、关联字段、分页）
> 结论摘要: **20 QPS 实测确认；638 条全量同步 <2 分钟可行；公式/关联字段 API 直接返回计算值与链接 ID，本地化设计成立**

---

## 1. 频率限制（20 QPS 确认）

| 项 | 结论 | 证据 |
|----|------|------|
| 记录读取接口 | 20 QPS（应用维度，tenant_access_token） | 飞书开放平台 API 文档：「该接口支持调用频率上限为 20 QPS」（bitable 记录列表/详情均此档） |
| 字段列表接口 | 20 QPS 同档 | 实测调用 bitable_v1_appTableField_list 正常 |
| 批量能力 | 记录搜索/列表单次返回上限 page_size ≤ 500（实测 100 安全） | lark-mcp 实测正常返回 |

**同步引擎 QPS 预算（638 条全量）**：
- 记录拉取：638 ÷ 100/页 ≈ 7 次请求；
- 字段 schema：1 次；关联子表（歌曲清单）：按量 ~10 次；User 反查（可选）：~8 次；
- 合计 <30 次请求 → 按 20 QPS 限制排队，**理论 <2 分钟内完成**（预留重试与节流后仍满足）。

## 2. 行数与容量上限

| 项 | 结论 |
|----|------|
| 单表行数 | 受 Base 版本/付费权益影响（免费版与付费版梯度不同，官方文档《多维表格常见上限》《付费权益说明》有明确数字，需按飞书侧当前版本确认） |
| 本案余量 | 638 条 ≪ 任何版本下限，**容量风险不成立**（SPEC v0.2 已把「百万级」假设删除） |
| 单单元格长度 | 文本字段有长度上限（长文本办案笔记需注意，实测安全） |
| 字段数上限 | Base 维字段数有限制；35 字段合规 |

> 设计上仍保留「10 万行」FTS 兜底与增长预警（年度新增 <500 条假设下 15 年无忧）。

## 3. 字段类型与 API 返回值（对应 35 字段设计）

| 类型 | API 返回值要点 | 本地建模 |
|------|----------------|----------|
| Text | 字符串原样 | TEXT |
| SingleSelect / MultiSelect | 选项名（SS 单值字符串；MS 字符串数组） | TEXT / JSON 数组，枚举字典归一 |
| Number | 数值 + formatter 展示（千分位） | REAL（金额/数量） |
| DateTime | 毫秒时间戳 | INTEGER epoch_ms |
| Formula | **返回公式计算结果值**（类型随公式：数值/字符串等） | 存计算值 + 本地复刻公式（口径契约，见 docs/03 §5） |
| Lookup | 返回目标字段聚合结果 | 存值 + 关联表冗余 |
| DuplexLink | 返回关联记录 ID 数组（含 title） | `song_case` 多对多映射表 |
| SingleLink | 返回单条关联记录 ID | `parent_id` 自关联 |
| User | 返回 user_id + name | users 字典表（反查 open_id→姓名可选） |

> 实测证据（lark-mcp，2026-08-13）：`bitable_v1_appTableRecord_search` 返回的公式字段值可直接读取（如对方诉求支持率 0.08/0.316 与学生计算一致）；金额单位元；多选与单选结构符合上表。

## 4. 关联字段与分页

| 项 | 结论 |
|----|------|
| 双向关联字段（DuplexLink） | 官方支持「双向关联」：A 表↔B 表（涉歌曲清单表 tblCGACAzAMGd5eX ↔ 案件表）；API 返回需**按 composer/member 结构解析**，本地映射为多对多 |
| 记录分页 | 使用 `page_token` 游标 + `page_size`；**必须处理「翻页期间数据变更」**：游标失效重试全量增量窗口 |
| 筛选 | 服务器端支持字段过滤（field_name[in] 等），部门筛选尽量下沉到服务端减少拉取量 |
| 排序 | 服务端排序字段有限；复杂排序建议本地排 |

## 5. 与同步引擎设计（SPEC 6.2）的映射结论

| SPEC 设计点 | 调研核验 |
|-------------|----------|
| 天级增量（03:00）+ 手动全量 + 单条刷新 | ✅ 可行；增量用 updated_at 窗口 + 游标双保险 |
| 100 条/请求批处理 | ✅ page_size≤500，取 100 安全且留限频余量 |
| 公式字段存计算值 | ✅ API 返回计算值；本地复刻便于脏数据处理时重算 |
| DuplexLink/song_case 多对多 | ✅ 结构解析已明确；歌曲表行数少，可全量拉取 |
| User 字段人员解析 | ✅ user_id 稳定；姓名随记录返回可免反查 |
| 失败重试 3 次退避 | ✅ 与 20 QPS 限频策略兼容（指数退避 + 随机抖动） |

---

## 6. 结论（写回 SPEC/设计）

1. QPS 与容量约束不构成瓶颈，SPEC v0.2 风险表修正成立；
2. 同步实现要点 = 游标分页 + 批处理 + 公式值/关联 ID 解析 + 原子替换；
3. 剩余外部不确定项：飞书 Base 版本与行数上限（部署期用 `/api/v1/sync/dryrun` 自检回显）；
4. 单条刷新与「飞书侧修改后本地 30 秒可见」的验收目标可通过单条拉取实现（1 请求/条）。
