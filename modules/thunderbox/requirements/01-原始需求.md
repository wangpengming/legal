### 关键业务规则（原型设计必须体现）

1. **部署状态机**：building / deploying → running（成功）/ build_failed（失败，可查构建日志）
2. **私有 Git 仓库**：必须提供 git_token，创建时服务端 `git ls-remote` 预检（无 token 直接拒绝 git_auth_failed）；Token 仅用于预检 + 注册 deploy key，不落库
3. **build_pack 四模式**：dockerfile（无检测，按 Dockerfile 构建）/ nixpacks（自动检测语言）/ static（纯静态，无构建）/ spa（前端框架，npm build → dist）
4. **数据库注入**：postgres 自动注入 DATABASE_URL（?sslmode=disable）+ POSTGRES_HOST/PORT/DB/USER/PASSWORD；sqlite 需应用声明卷覆盖 /data
5. **卷挂载**：Docker 格式 `source:target[:ro]`；`/` 开头=bind mount，否则具名卷；config 改 volumes 是**替换式（破坏性）**
6. **回滚安全**：只改部署代码/commit，不碰数据库与卷
7. **删除红线**：应用删除 / 数据库删除在 MCP 侧一律禁用（走管理后台），UI 须体现该边界（提示引导而不是报错感）

## 三、安全上下文

- Token（Bearer）由本模块后端持有，读取自 `.env`（`THUNDERBOX_API_URL` + `THUNDERBOX_TOKEN`），**绝不进入前端 bundle**
- 前端 → 后端 REST → 后端 → MCP（token 注入）三段式，浏览器永不接触 token
- 操作审计：所有写操作（create/deploy/rollback/control/config/db 操作）记录审计日志（时间/操作/目标/结果）
- 二次确认：部署/回滚/停止/改访问模式等有副作用操作必须确认弹窗
